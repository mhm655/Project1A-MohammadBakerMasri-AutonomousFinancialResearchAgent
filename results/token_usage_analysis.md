## Recommendations

Context for these numbers: the Day 11 runs went out on 2026-10-01 after the free Gemini quota for the day was used up, so 75 of 78 calls went to Groq (`gpt-oss-120b` and `qwen3.8-27b`). Totals are 260,476 tokens for eight reports, a mean of 32,560 per challenge and 25 tokens per report word.

1. **Execution calls are the main cost (56% of tokens, 45 calls).**
   - Each ReAct execution call sends the JSON schemas of every research tool, plus up to 1,800 characters of dependency evidence. That averages 3,157 prompt tokens and only 51 completion tokens.
   - **Day 13 fix:** send only the planned tool's schema, with the others listed by name. This should cut roughly 2,000 tokens per call, about 90,000 tokens (35%) across the eight runs.
2. **Some execution calls only repaired arguments, and are now removed.**
   - C3, C4, C5 and C7 spent execution calls turning names such as `s2.revenue_FY2026` into numbers. Some of those repairs failed, so derived figures were lost.
   - The Day 12 fix (`agent/references.py`) now resolves these references without the LLM: every resolvable calculation costs zero LLM calls.
3. **Rate limits cost time, not tokens.**
   - The 162 "LLM failures" are 139 Groq HTTP 429 rate-limit responses, 8 Gemini daily-quota errors, 12 refused connections to an Ollama server that was not running, and 3 bad requests.
   - A rejected request is not billed, so these did not cost tokens. They did add latency: C7 took 245 s, 68 failures.
   - **Day 13 fix:** keep a provider marked down for the rest of the run once it reports `quota_exhausted`, and skip Ollama when its port is closed.
4. **Synthesis is capped too tightly.**
   - Synthesis is 22% of tokens. It is held to `max_prompt_tokens = 6000`, which suits the smallest free model but starves Gemini, whose context window is about 1 million tokens.
   - The reports came out at 651–1,651 words, against the spec's 3–20 pages (about 1,500–10,000 words). The short evidence window is the main cause of the low analytical-depth scores (AD-1 to AD-4).
   - One synthesis prompt reached 107% of the cap: the local tokenizer under-counts Qwen tokens.
   - **Day 13 fix:** make the cap depend on the provider, for example 6,000 on Groq and 24,000 on Gemini, and leave 10% headroom for tokenizer differences.
5. **Review calls could be skipped.**
   - The 16 review calls (12%) mostly confirmed the plan was complete; C1 and C3 had review replies of only 14–15 tokens.
   - A cheap deterministic check (are all template sections covered by done steps?) could skip the LLM review when nothing is missing.
6. **Memory-led research (C7) is the most expensive per word: 45.7 tokens per word, 23 calls.**
   - The planner scheduled earnings-transcript steps that could not run without tickers. The LLM judge noted this too (AB-3 = 2/5).
   - The fix is a planner rule: for `cross_memory` queries, draw tickers from recalled memory before planning company-specific tools.

Expected effect: about 35–45% fewer tokens per report (items 1, 2 and 5), and no extra tokens spent on longer, better-grounded reports (item 4). These estimates will be measured on Day 13 (`results/evaluation_report_v2.md`).
